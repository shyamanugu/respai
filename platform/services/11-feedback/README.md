# Feedback Loop

## What this is
Captures a rating on a step's output — from an agent, an end customer, or a reviewer — and, when that feedback includes a human correction, promotes it into a golden-dataset case Evaluation Gate (04) can run against. This is the mechanism that closes the loop this platform's whole gating story depends on: a production mistake, once corrected once by a human, becomes a permanent regression test so it can never silently reoccur.

## Not wired into Orchestration
Unlike Prompt Management, Data & Tools, Guardrails, and Observability, this component makes **no change to Orchestration (08)**. Feedback is fundamentally not something a `Step` produces during `.run()` — it's collected afterward, out of band, once a human has actually seen the output (an agent reviewing a suggested reply, a customer rating an interaction). It only needs `session_id` (already generated by `State`) as a correlation key, which it reads, not imports — this component has no dependency on Orchestration at all.

## Storage: three backends
| Store | Azure dependency | Use |
|---|---|---|
| `InMemoryFeedbackStore` | none | tests |
| `JsonlFileFeedbackStore` | none | a single usecase's local/dev use — zero setup |
| `AzureBlobFeedbackStore` | Azure Blob Storage | shared, durable storage once a usecase is live |

All three satisfy the same `FeedbackStore` shape (`record`, `list_for_session`) — swapping backends is a constructor change, not a call-site change. `AzureBlobFeedbackStore` appends each event as one JSON line to a single append blob per environment; its SDK is imported lazily inside `__post_init__`, so a usecase using only the free stores doesn't need `azure-storage-blob` installed. Not exercised against a live resource by the automated test suite — same posture as every other real-Azure backend in this platform.

## The promotion bridge to Evaluation Gate
`promote_to_golden_dataset(events, output_path)` writes one `exact_match` golden-dataset case per feedback event that carries a `corrected_output` — `original_input` becomes the case's `input`, the correction becomes its `expected` value. This is a **data-format bridge, not a code dependency**: this component doesn't import `evaluation_gate`, it only writes JSONL lines matching the format that component's README documents (`docs/decisions/0008-evaluation-gate-scope.md`). A format mismatch would surface loudly the moment someone tries to load the file, not silently.

Feedback with no correction (a plain thumbs-up/down) is **not** promoted — a rating with nothing to compare against isn't a regression case yet. See "Revisit When" in `docs/decisions/0011-feedback-scope.md` for where that signal is expected to go instead.

## File layout
```
src/feedback/
├── types.py                          # FeedbackEvent
├── store.py                          # FeedbackStore protocol, InMemoryFeedbackStore, JsonlFileFeedbackStore
├── blob_store.py                      # AzureBlobFeedbackStore — real backend, lazy SDK import
└── promotion.py                        # promote_to_golden_dataset()

tests/
├── test_store.py                      # in-memory + jsonl persistence across instances
└── test_promotion.py                   # only corrected events promoted, appends to existing file
```

## Prerequisites
None for `InMemoryFeedbackStore`/`JsonlFileFeedbackStore`. `.env.local` populated with `AZURE_STORAGE_CONNECTION_STRING` only if a usecase constructs `AzureBlobFeedbackStore`.

## Local development
```bash
pip install -r requirements.txt
pytest
```
Every test runs against `InMemoryFeedbackStore`/`JsonlFileFeedbackStore` — no Azure credentials, no network call, no dependency on any other platform component (the third fully standalone component, alongside Guardrails and Evaluation Gate's core logic).

Importable as the `feedback` package, per `docs/decisions/0004-python-package-naming.md`.

## Setup (once ready to provision)
```bash
az deployment group create \
  --resource-group rg-llmops-dev-eastus-001 \
  --template-file infra/storage-account.bicep \
  --parameters infra/main.parameters.dev.json
```
Nothing above has been run yet in this build. The two free stores need no Azure resource at all.

## Dependencies
- Depends on: nothing (no other platform component is a prerequisite; the promotion bridge is a documented file format, not an import)
- Depended on by: nothing yet — a real usecase's serving layer (component 10, not built) is the expected caller once one exists; Evaluation Gate (04) is the expected consumer of promoted golden-dataset files, via its own `load_dataset()`, not a call into this component

## Cost notes
`InMemoryFeedbackStore`/`JsonlFileFeedbackStore`: free. `AzureBlobFeedbackStore`: Blob Storage's standard per-GB + per-operation pricing once provisioned; nothing is provisioned yet.
